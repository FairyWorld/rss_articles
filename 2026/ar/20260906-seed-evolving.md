## 一、引言

前些日子，字节的朋友邀请我内测，他们最新的基座模型[豆包 Seed-2.1-Pro-0915](https://mp.weixin.qq.com/s/Fp_mgF6wxMk0bkUVBqOKqA)。

![](https://cdn.beekka.com/blogimg/asset/202609/bg2026091613.webp)

目前，它的新版本都会附加发布日期，[Seed-2.1-Pro-0915](https://ark.volcengine.com/region:cn-beijing/model/detail?_vtm_=a441938.b75322.0_0.0_0.0.174_7680087491668166163&name=doubao-seed-2-1-pro) 就是今年9月15日推出的最新版本。

为了测试它的多模态编程能力，我用它生成了一个互动式 3D 数字西湖。我在杭州住了好几年，对西湖很熟悉，正好看看大模型的还原度有多高。

## 二、开发模式的变化

开始之前，我简单说一下，这个豆包 Seed 2.1 Pro 模型是怎么回事。

它的正式推出是在今年6月份，按照常理来说，下一个版本应该是 Seed 2.2。但是，开发团队做了一个重大决定：改变开发模式。

他们在 Seed 2.1 Pro 的基础上，又推出另一个基座模型“[豆包 Seed Evolving](https://ark.volcengine.com/region:cn-beijing/model/detail?_vtm_=a441938.b105393.0_0.0_0.0.73_7683704596585268770&name=doubao-seed-evolving)”。两者的代码完全一样，唯一的不同是，**后者没有版本号**。

Seed Evolving 是一个主打持续更新的模型，只有模型名，没有版本号。你通过名称调用它，不需要加版本号，它始终指向最新版本。就我所知，这好像是第一个不带版本号的大模型。

它一直在高频更新，每月有两到三次的发布，只用发布日期区分不同的版本，不再人为强加一个版本号了。

这样做的主要原因是，（绝大多数）**用户根本不在意版本号，只想用最新最强的代码**。没有了版本号，用户就不需要手动更新模型版本了，模型后台常态化自动更新，你调用的永远都是最新版本，反而更省事。对于模型的开发者也省事，不必维护旧版本了，可以集中精力搞好当前版本。

事实上，这个模型起名为 Seed Evolving，原因就是英文单词 evolvlng 的意思就是“（持续）进化”。

回到 Seed 2.1 Pro，它和 Seed Evolving 就是同一个模型，**每当 Seed Evolving 发布重大版本时，它就会随之更新**。

所以，Seed-2.1-Pro-0915 就是这么来的，它实际就是 Seed Evolving 9月份最新版本。

## 三、三大能力

一直以来，豆包 Seed 2.1 Pro 作为基座模型，主打三大能力：**Coding（编码）、Agent（工具）、VLM（视觉）**。

这三大能力号称都非常强，而且比较均衡，没有明显短板，毕竟它是豆包背后的大模型。

![](https://cdn.beekka.com/blogimg/asset/202609/bg2026091614.webp)

这次的 0915 新版本在这三个方面，都有增强。

> **（1）Coding**：可以读懂非常复杂的大型软件项目，多模态看图生成代码能力更强。
> 
> **（2）Agent**：强调可靠性，增加了搜索结果的真实度，幻觉更少，复杂的长程任务更稳。
> 
> **（3）VLM**：多模态理解能力更强，可以依据视频进行推理，能够处理 3D 物体与密集图文。

下面，我就用“数字西湖”项目，测一下它的多模态的编码能力。

## 四、数字西湖

我的提示词如下。

> [提示词] 根据网上的地图，实现一个 3D 的西湖旅游全景图，要求是可以交互、滚轮缩放、拖动旋转，点击某个地点后，可以自动飞过去。

这个项目大概比较复杂，输入提示词以后，它足足跑了2小时15分钟，花费的 API 费用为28元人民币。

第一次出来的结果，我要求的界面和功能就都实现了：滚轮缩放，拖动旋转，点击某个地标，就自动飞到该地点，并提供360度自动环视的视角。

一次就能做到了这种程度，有点出乎我的意料。当然也不是没有问题，我给大家看一些细节。

首先是 3D 西湖全景。

![](https://cdn.beekka.com/blogimg/asset/202609/bg2026091003.webp)

它正确标识出了“西湖十景”，位置全部正确，但白堤和苏堤连起来了，实际上，两者之间隔着一小片湖面。

其次是雷峰塔和六和塔。

![](https://cdn.beekka.com/blogimg/asset/202609/bg2026091005.webp)

可以看到，两座塔都在山坳里面。这符合实际情况，它们确实都在西湖群山的山脚。

最后，还有一些生动的小细节，比如水里有船，而且船在前进。

![](https://cdn.beekka.com/blogimg/asset/202609/bg2026091007.webp)

不过，比例有点问题，船和湖边的亭子过大，跟西湖面积不成比例。

总的来说，只根据一句提示词，就能做出这种效果，所有的基本要求都正确实现了，我觉得相当可以。

## 六、总结

经过“数字西湖”这个项目，我认为，Seed-2.1-Pro-0915 模型的表现令人惊喜。

看上去，它的编码能力很不错，能够处理这样复杂的 3D 网页项目，确实符合它作为 Seed 系列最强基座模型的定位。

而且，就像前面说的，它背后的 Seed Evolving 模型始终在持续发布，这代表着它的功能还会不断改进和增强。

以后，以后提到一线的国产模型时，我会把 Seed 2.1 Pro（或者 Seed Evolving）加进去。

## 二、为什么放弃版本号

（1）保证持续性。让用户始终使用“当前最强版本”，不必手动更新版本。
- 用户需求多样化，Agent 与 Coding 工具日新月异，模型需要跟上这个节奏。
- 版本号会慢慢淡出，模型越来越像一件产品。
- 集中精力维护最新版本。
- 常态化后台自动更新，方便用户。

（2）追求更强的模型能力，周更有利促进模型快速跟上发展。

Seed evolving 着重发展的三大能力：Agent、Coding 和 VLM（视觉）。

## 持续与看见

效果本身早已不是胜负手。当各家模型都能把常见任务做得八九不离十，真正拉开差距的其实是另外两件事。

周更的原因：（1）保证持续性。让用户手里始终握着“当前最强的那一个”，而不是某个发布日之后就慢慢过时的版本。

用户需求多样化，Agent 与 Coding 工具日新月异，模型需要跟上这个节奏。

- 版本号会慢慢淡出，模型越来越像一件产品。就像今天没人关心自己的 Mac 跑在哪个小版本上，系统在后台就把你带到了最新；模型也该默认指向最新最强，用户不必在一堆版本里做选择题。
- 集中精力维护最新版本。
- 后台自动更新早已是常态。

（2）另一件是看见。当 Coding 和 Agent 强到成为入场券，视觉理解（VLM）会接棒成为下一个分水岭。Design-to-Code、GUI 操作这些最值钱的场景，归根到底都要求模型“能看懂屏幕”；而现实里大量系统压根没有干净的 API，屏幕才是真正的长尾入口——这一点后面用数据说话。
