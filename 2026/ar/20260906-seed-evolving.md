## 二、豆包 Seed Evolving 模型

我先说一下豆包 Seed Evolving 模型，它有一个地方，跟其他模型都不一样。

**它没有任何版本号**，只有一个模型名。你通过名称调用它，不需要加版本号，它始终指向最新版本。就我所知，这好像是第一个不带版本号的大模型。

刚看到的时候，我觉得这种做法很奇特，但仔细一想，反而觉得不带版本号有合理的一面。

它是一个**高频更新的模型**，版本号确实不是很有必要。代码每天都在改动，最自然的做法就是日常发布时标记一下日期，人为强加一个版本号，反而显得有点多余。

（绝大多数）**用户根本不在意版本号，只想用最新最强的代码**。通行的做法是，每当有新版本，用户就去 Agent 工具里面，手动更新一下所要调用的模型版本，其实很麻烦。

Seed Evolving 索性就只有模型名称，后台常态化自动更新，你调用的永远都是最新版本，这样最省事。另一个好处是，不必维护旧版本了，可以集中精力搞好当前版本。

事实上，这个模型起名为 Seed Evolving，原因就是英文单词 evolvlng 的意思就是“（持续）进化”。

## 三、三大能力

官方宣传，Seed Evolving 模型作为基座模型，主打三大能力：**Coding（编码）、Agent（工具）、VLM（视觉）**。

这三大能力号称都非常强，而且比较均衡，没有明显短板。

- Coding：可以生成非常复杂的大型软件项目。
- Agent：可以并发处理长程任务。
- VLM：视觉理解能力更是世界一流，看同系列的 Seedream 和 Seedance 模型就知道了。

下面，我就用“数字西湖”项目，测一下它的编码能力。

## 四、数字西湖

我的提示词如下。

> [提示词] 根据网上的地图，实现一个 3D 的西湖旅游全景图，要求是可以交互、滚轮缩放、拖动旋转，点击某个地点后，可以自动飞过去。

这个项目大概比较复杂，输入提示词以后，它足足跑了2小时15分钟，花费的 API 费用为28元人民币。

第一次出来的结果，我要求的界面和功能就都实现了：滚轮缩放，拖动旋转，点击某个地标，就自动飞到该地点，并提供360度自动环视的视角。

一次就能做到了这种程度，有点出乎我的意料。当然也不是没有问题，我给大家看一些细节。

## 二、为什么放弃版本号

（1）保证持续性。让用户始终使用“当前最强版本”，不必手动更新版本。
- 用户需求多样化，Agent 与 Coding 工具日新月异，模型需要跟上这个节奏。
- 版本号会慢慢淡出，模型越来越像一件产品。
- 集中精力维护最新版本。
- 常态化后台自动更新，方便用户。

（2）追求更强的模型能力，周更有利促进模型快速跟上发展。

Seed evolving 着重发展的三大能力：Agent、Coding 和 VLM（视觉）。

## 持续与看见

效果本身早已不是胜负手。当各家模型都能把常见任务做得八九不离十，真正拉开差距的其实是另外两件事。

周更的原因：（1）保证持续性。让用户手里始终握着“当前最强的那一个”，而不是某个发布日之后就慢慢过时的版本。

用户需求多样化，Agent 与 Coding 工具日新月异，模型需要跟上这个节奏。

- 版本号会慢慢淡出，模型越来越像一件产品。就像今天没人关心自己的 Mac 跑在哪个小版本上，系统在后台就把你带到了最新；模型也该默认指向最新最强，用户不必在一堆版本里做选择题。
- 集中精力维护最新版本。
- 后台自动更新早已是常态。

（2）另一件是看见。当 Coding 和 Agent 强到成为入场券，视觉理解（VLM）会接棒成为下一个分水岭。Design-to-Code、GUI 操作这些最值钱的场景，归根到底都要求模型“能看懂屏幕”；而现实里大量系统压根没有干净的 API，屏幕才是真正的长尾入口——这一点后面用数据说话。
