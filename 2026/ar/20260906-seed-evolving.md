# Seed Evolving

# 我用豆包 Seed Evolving 模型生成了一个数字西湖

## 一、豆包的模型

上周末，我测试“[豆包工作](https://www.doubao.com/work)”，对它印象不错，顺便查了一下它的后台模型。

它用的是自研模型，主力的基座模型是 Seed 2.1 Pro，再加上同系列的图像模型 Seedream 和视频模型 Seedance。

意外的是，我在官网上看到，Seed Pro 竟然已经有了后续模型 [Seed Evolving](https://ark.volcengine.com/region:cn-beijing/model/detail?_vtm_=a441938.b75322.0_0.0_0.0.140_7680087491668166163&name=doubao-seed-evolving)，而且连发布模式也改了。

![](https://cdn.beekka.com/blogimg/asset/202609/bg2026091015.webp)

这就是说，豆包 Seed 大模型的最新版本，已经从 Seed 2.1 Pro 变成了 Seed Evolving，但是**后者竟然没有任何版本号，只有一个模型名称**。

你通过名称调用它，不带任何版本号，它始终指向最新版本。就我所知，这好像是第一个不带版本号的大模型。

## 二、为什么没有版本号

刚看到的时候，我觉得这种做法很新奇，但仔细一想，反而觉得不带版本号有合理的一面。

如果一个大模型在**持续高频更新**，版本号确实不是很有必要。

代码每天都在改动，最自然的做法就是日常发布时标记一下日期，人为强加一个版本号，反而显得有点多余。

（绝大多数）**用户根本不在意版本号，只想用最新最强的代码**。通行的做法是，每当有新版本，用户就去 Agent 工具里面，手动更新一下所要调用的模型版本，其实很麻烦。

Seed Evolving 索性就只有模型名称，后台常态化自动更新，你调用的永远都是最新版本，这样最省事。

对于大模型公司来说，另一个好处是，不必维护旧版本了，可以集中精力搞好当前版本。

总之，Seed Evolving 改变模型发布模式，不再给出版本号，以便更适配它“持续更新”的模式。它名字里面的英文单词 evolvlng，本义就是“（持续）进化”。

## 三、三大能力

作为 Seed 家族的基座模型，它每天要处理上亿次的请求，这必然要求它必须是一个强大的通用模型，各种能力均衡，不能有明显的短板。

根据官方宣传，它主攻三大能力：**Coding（编码）、Agent（工具）、VLM（工具）**。

这三种能力都必须很强，位列业内前茅：Coding 可以生成非常复杂的大型软件项目；Agent 可以并发处理长程任务，豆包的工作任务模式就基于这个能力；VLM 视觉处理能力更是世界一流，看同系列的 Seedream 和 Seedance 模型就知道了。

为了了解它的真实能力，我用它做了一个“数字西湖”项目。下面，就给大家看一下做出来的结果。

## 四、数字西湖

正好上周，OpenAI 公司发布了最新的 GPT-6 Astra 模型，号称是当下的最强模型之一，有人说比 Fable 5.1 还要强。

[网友](https://x.com/NFT_Chen/status/2096143589151756638)用它生成了一个数字版的 3D 杭州城。我看到以后，不禁想拿 Seed Evolving 也来试一下。

Seed Evolving 不是号称视觉能力很强吗，我提交一个原版网站的视频文件，让它自己学习这种风格，从头实现一个同样的网站。

> [提示词] 采用视频文件 hangzhou-3d.mov 的风格，根据网上的地图，实现一个 3D 的西湖旅游全景图，要求是可以交互、滚轮缩放、拖动旋转，点击某个地点后，可以自动飞过去。

这个项目比较复杂，输入提示词以后，它足足跑了2小时15分钟，花费的 API 费用为28元人民币。下面就是第一个版本。

可以看到，我要求的界面和功能都实现了，滚轮缩放，拖动旋转，点击某个地标，就自动飞到该地点，并提供360度自动环视的视角。第一次尝试，能做到了这种程度，有点出乎我的意料。

我给大家看一些细节，首先是 3D 西湖全景。

![](https://cdn.beekka.com/blogimg/asset/202609/bg2026091003.webp)

Seed 标识出了“西湖十景”，位置全部正确。遗憾的是，白堤和苏堤连起来了，实际上，两者之间隔着一小片湖面。

接着是雷峰塔和六和塔。

![](https://cdn.beekka.com/blogimg/asset/202609/bg2026091005.webp)

可以看到，两座塔都在山坳里面，实际位置就是这样，它们确实都在西湖群山的山脚。

此外，还有一些生动的小细节，比如水里有船，而且船在前进。

![](https://cdn.beekka.com/blogimg/asset/202609/bg2026091007.webp)

不过，比例有点问题，船和湖边的亭子过大，跟西湖面积不成比例，后面让模型调一下比例尺。

总之，Seed 的这个实现，我觉得还不错。只参考一个视频，就做到这个程度，这说明它的视觉理解能力和编码能力，确实相当可以。

网站开发的模式真的变了，以后只要提供图片或视频，再给出几点文字指令，大模型就可以高还原度地实现出来。

## 六、总结

经过“数字西湖”这个项目，我认为，Seed Evolving 模型的表现令人惊喜。

看上去，它的三大能力（编码、工具、视觉）都很有水准，并且均衡。它作为 Seed 系列最强的基座模型，能经受住豆包的使用，应该差不了。

而且，就像开头说的，它没有版本号，始终在持续发布，这代表着它的功能还会不断改进和增强。

以后，大家再考虑使用哪些一线的国产模型时，应该把 Seed Evolving 考虑进去。

（完）

## 一、引言

介绍基本情况。

字节将 Seed 大模型改变了发布模式，不使用版本号，而是持续更新，模型重命名为 Seed-evolving。

据我所知，这是第一家放弃版本号的大模型。

## 二、为什么放弃版本号

（1）保证持续性。让用户始终使用“当前最强版本”，不必手动更新版本。
- 用户需求多样化，Agent 与 Coding 工具日新月异，模型需要跟上这个节奏。
- 版本号会慢慢淡出，模型越来越像一件产品。
- 集中精力维护最新版本。
- 常态化后台自动更新，方便用户。

（2）追求更强的模型能力，周更有利促进模型快速跟上发展。

Seed evolving 着重发展的三大能力：Agent、Coding 和 VLM（视觉）。

## 持续与看见

效果本身早已不是胜负手。当各家模型都能把常见任务做得八九不离十，真正拉开差距的其实是另外两件事。

周更的原因：（1）保证持续性。让用户手里始终握着“当前最强的那一个”，而不是某个发布日之后就慢慢过时的版本。

用户需求多样化，Agent 与 Coding 工具日新月异，模型需要跟上这个节奏。

- 版本号会慢慢淡出，模型越来越像一件产品。就像今天没人关心自己的 Mac 跑在哪个小版本上，系统在后台就把你带到了最新；模型也该默认指向最新最强，用户不必在一堆版本里做选择题。
- 集中精力维护最新版本。
- 后台自动更新早已是常态。

（2）另一件是看见。当 Coding 和 Agent 强到成为入场券，视觉理解（VLM）会接棒成为下一个分水岭。Design-to-Code、GUI 操作这些最值钱的场景，归根到底都要求模型“能看懂屏幕”；而现实里大量系统压根没有干净的 API，屏幕才是真正的长尾入口——这一点后面用数据说话。
