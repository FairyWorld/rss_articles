# Seed Evolving

《Seed 模型放弃了版本号，我用它生成了一个数字西湖》

## 一、豆包背后的模型

上个周末，我在测试“[豆包工作](https://www.doubao.com/work)”，意外发现，**豆包背后的模型变了**。

这件事还挺有趣，是一种全新的情况，值得大家了解。

我们知道，豆包用的是自研模型，主要是基座模型 Seed 2.1 Pro，以及同系列的图像模型 Seedream 和视频模型 Seedance。

但是，豆包最近把 Seed 2.1 Pro 换掉了。

准确说，不是换掉，而是改变模型的开发模式，就顺便连模型的名称一起改了。

豆包现在使用的基座模型叫做 Seed Evolving，最有趣的地方是，**这个模型没有版本号**。

别的模型都有版本号，比如 Seed 2.1 Pro 下一个版本可能是 2.2，也可能是3.0。但是，Seed Evolving 没有，只有一个模型名称。

你只能通过名称引用它，不需要给出版本号，它保证你用的始终是最新版本。据我所知，这好像是第一家放弃版本号的大模型。

## 二、为什么放弃版本号

我第一次看到的时候，觉得很新奇，但是仔细一想，觉得放弃版本号反而是很合理的做法。

如果一个大模型在**持续进化**，版本号其实不是很有必要。代码每天都在改动，发布时最自然的做法就是标记一下日期，人为强加一个版本号，反而显得有点多余。

最重要的一点是，（绝大多数）用户根本不在意版本号，只想要最新最强的代码。现在通行的做法是，每当有版本，用户就去 Agent 工具里面，手动更新一下调用的模型版本，其实很麻烦。

不如索性像 Seed Evolving 一样，只写模型名称，后台常态化自动更新，永远调用的都是最新版本，来得省事。

对于模型开发者来说，这样也有好处，不必维护旧版本了，集中精力搞好当前版本。

Seed Evolving 名称里面的英文单词 evolvlng，意思就是“（持续）进化”。

## 三、三大能力

除了没有了版本号，Seed Evolving 作为豆包背后的主力模型，本身也有特点。

它是一个通用模型，**Coding（编码）、Agent（工具）、VLM（工具）这三大能力都必须很强**，才能满足需要。它的能力决定了豆包的上限。

根据官方宣传，这三大能力正是它的卖点和主打方向。Coding 可以生成非常复杂的软件项目；Agent 可以并发处理长程任务，“豆包工作”就是基于这个能力；VLM 视觉处理能力更是世界一流，看同系列的 Seedream 和 Seedance 就知道了。

下面，我就给大家看一下，我用它做的东西。

## 四、数字西湖

我的想法是，让它生成一个复杂的项目，看看它的能力。

正好上周，OpenAI 公司发布了最新的 GPT-6 Astra，号称是目前最强的模型之一，有人说比 Fable 5.1 还要强。

[网友](https://x.com/NFT_Chen/status/2096143589151756638)就用它生成了一个数字版的 3D 杭州城，非常炫酷。

我就想，Seed Evolving 不是号称视觉能力很强吗，把这个视觉提交给它，让它从头实现一个，看看行不行。

## 一、引言

介绍基本情况。

字节将 Seed 大模型改变了发布模式，不使用版本号，而是持续更新，模型重命名为 Seed-evolving。

据我所知，这是第一家放弃版本号的大模型。

## 二、为什么放弃版本号

（1）保证持续性。让用户始终使用“当前最强版本”，不必手动更新版本。
- 用户需求多样化，Agent 与 Coding 工具日新月异，模型需要跟上这个节奏。
- 版本号会慢慢淡出，模型越来越像一件产品。
- 集中精力维护最新版本。
- 常态化后台自动更新，方便用户。

（2）追求更强的模型能力，周更有利促进模型快速跟上发展。

Seed evolving 着重发展的三大能力：Agent、Coding 和 VLM（视觉）。

## 持续与看见

效果本身早已不是胜负手。当各家模型都能把常见任务做得八九不离十，真正拉开差距的其实是另外两件事。

周更的原因：（1）保证持续性。让用户手里始终握着“当前最强的那一个”，而不是某个发布日之后就慢慢过时的版本。

用户需求多样化，Agent 与 Coding 工具日新月异，模型需要跟上这个节奏。

- 版本号会慢慢淡出，模型越来越像一件产品。就像今天没人关心自己的 Mac 跑在哪个小版本上，系统在后台就把你带到了最新；模型也该默认指向最新最强，用户不必在一堆版本里做选择题。
- 集中精力维护最新版本。
- 后台自动更新早已是常态。

（2）另一件是看见。当 Coding 和 Agent 强到成为入场券，视觉理解（VLM）会接棒成为下一个分水岭。Design-to-Code、GUI 操作这些最值钱的场景，归根到底都要求模型“能看懂屏幕”；而现实里大量系统压根没有干净的 API，屏幕才是真正的长尾入口——这一点后面用数据说话。
